# Task_Manager
Desktop task manager and calendar application built with C# and WPF
# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Курсовой проект «TaskFlow — настольное приложение для управления задачами и календарного планирования»

### 1. Общие сведения

**1.1. Наименование проекта**

TaskFlow — настольное приложение для управления задачами, планирования событий и организации личного времени.

**1.2. Назначение разработки**

Разрабатываемое программное обеспечение предназначено для организации личного времени пользователя посредством объединения функциональности менеджера задач (Task Manager) и календарного планировщика.

Приложение должно предоставлять возможность создавать, редактировать, удалять и отслеживать задачи, планировать события, устанавливать сроки выполнения, получать напоминания и просматривать запланированные мероприятия в календаре.

Программа должна функционировать как самостоятельное настольное приложение с графическим интерфейсом пользователя и локальным хранением данных.

**1.3. Цель разработки**

Целью курсового проекта является разработка настольного приложения на языке C# с использованием технологии WPF, обеспечивающего удобное управление задачами и календарное планирование.

В рамках проекта необходимо реализовать:
- создание и управление задачами;
- календарь с несколькими режимами отображения;
- создание и управление календарными событиями;
- систему категорий и приоритетов;
- систему напоминаний;
- отслеживание прогресса выполнения задач;
- поиск, сортировку и фильтрацию информации;
- статистику продуктивности пользователя;
- сохранение данных в локальной базе данных.

### 2. Функциональные требования

#### 2.1. Главное окно приложения

При запуске программы пользователь должен попадать в главное окно приложения.

Главное окно должно содержать боковую панель навигации, центральную рабочую область и дополнительные элементы управления.

Основные разделы приложения:

1. **Dashboard** — главная страница.
2. **My Tasks** — управление задачами.
3. **Calendar** — календарное планирование.
4. **Events** — управление событиями.
5. **Categories** — управление категориями.
6. **Reminders** — напоминания.
7. **Statistics** — статистика выполнения задач.
8. **Settings** — настройки приложения.

Переход между разделами должен осуществляться без необходимости закрывать главное окно приложения.

#### 2.2. Главная страница (Dashboard)

Главная страница должна предоставлять пользователю общую информацию о текущей загруженности и предстоящих делах.

Необходимо реализовать отображение следующих данных:
- приветствие пользователя;
- текущая дата;
- общее количество активных задач;
- количество выполненных задач;
- количество просроченных задач;
- список задач на текущий день;
- ближайшие запланированные события;
- краткая статистика выполнения задач;
- быстрый доступ к созданию новой задачи или события.

Информация на главной странице должна обновляться после добавления, изменения или удаления задач и событий.

#### 2.3. Менеджер задач (Task Manager)

Система должна предоставлять возможность полноценного управления задачами.

**Создание задачи**

При создании задачи пользователь должен иметь возможность указать:
- название задачи;
- описание;
- дату создания;
- срок выполнения (дедлайн);
- дату и время начала выполнения (необязательно);
- приоритет;
- категорию;
- статус выполнения;
- необходимость напоминания.

**Приоритеты задач:**
- низкий;
- средний;
- высокий;
- критический.

**Статусы задач:**
- новая;
- в процессе выполнения;
- выполнена;
- отменена.

**Операции с задачами:**
- создание новой задачи;
- просмотр подробной информации;
- редактирование;
- удаление;
- изменение статуса;
- изменение приоритета;
- перенос срока выполнения;
- поиск по названию;
- сортировка по дате, приоритету и статусу;
- фильтрация по категориям и срокам выполнения.

Пользователь должен иметь возможность просматривать все созданные задачи в едином списке независимо от наличия у них конкретной даты выполнения.

При изменении статуса задачи на «Выполнена» система должна автоматически учитывать это изменение в статистике.

#### 2.4. Календарь

Календарь является одним из основных компонентов приложения.

Он должен обеспечивать визуальное представление задач и событий в соответствии с выбранными датами и временными промежутками.

**Режимы отображения календаря:**

- **День** — отображение задач и событий за выбранный день с указанием времени.
- **Неделя** — отображение расписания на семь дней с возможностью просмотра временных интервалов.
- **Месяц** — отображение календарной сетки с запланированными задачами и событиями.
- **Список** — отображение предстоящих задач и событий в хронологическом порядке.

**Функциональные возможности календаря:**
- переключение между датами;
- переход к текущему дню;
- просмотр задач и событий на выбранную дату;
- создание задачи непосредственно из календаря;
- создание календарного события;
- редактирование запланированных элементов;
- перенос элементов на другую дату;
- отображение продолжительности событий;
- визуальное различие между задачами и событиями;
- цветовое обозначение категорий и приоритетов.

Календарь должен автоматически отображать задачи, имеющие назначенные даты, а также отдельно созданные события.

При выборе определённой даты пользователь должен иметь возможность просматривать все запланированные на неё задачи и события.

#### 2.5. Управление календарными событиями

Помимо задач, пользователь должен иметь возможность создавать отдельные календарные события.

Событие представляет собой запланированное мероприятие или временной интервал, который необходимо учитывать при планировании дня.

При создании события пользователь должен иметь возможность указать:
- название события;
- описание;
- дату;
- время начала;
- время окончания;
- место проведения (необязательно);
- категорию;
- цветовое обозначение;
- необходимость напоминания.

**Примеры событий:**
- занятия в университете;
- рабочие встречи;
- тренировки;
- консультации;
- поездки;
- личные мероприятия.

Пользователь должен иметь возможность:
- создавать события;
- просматривать подробную информацию;
- редактировать события;
- удалять события;
- изменять дату и время проведения.

Система должна проверять корректность временного интервала: время окончания события не может быть раньше времени начала.

#### 2.6. Категории задач и событий

Для удобной организации информации система должна поддерживать категории.

Пользователь должен иметь возможность:
- создавать собственные категории;
- задавать название категории;
- выбирать цвет категории;
- редактировать категории;
- удалять категории;
- назначать категории задачам и событиям.

Примеры стандартных категорий:
- работа;
- учёба;
- личное;
- спорт;
- отдых.

Категории должны использоваться для визуального обозначения и фильтрации задач и событий.

#### 2.7. Система напоминаний

Приложение должно предоставлять возможность устанавливать напоминания о предстоящих задачах и событиях.

Необходимо реализовать:
- настройку времени напоминания;
- напоминание о приближении срока выполнения задачи;
- напоминание о предстоящем событии;
- отображение просроченных задач;
- список активных и просмотренных уведомлений внутри приложения.

Система должна проверять наступление времени напоминания и отображать соответствующее уведомление пользователю.

Проверка напоминаний должна осуществляться в фоновом режиме во время работы приложения.

Дополнительно допускается реализация системных уведомлений Windows.

#### 2.8. Поиск, сортировка и фильтрация

Система должна предоставлять инструменты для быстрого поиска необходимой информации.

Необходимо реализовать:
- поиск задач и событий по названию;
- фильтрацию по категориям;
- фильтрацию по статусу;
- фильтрацию по приоритету;
- фильтрацию по временным промежуткам;
- сортировку по дате создания;
- сортировку по сроку выполнения;
- сортировку по приоритету.

Результаты поиска и фильтрации должны отображаться в соответствующих разделах приложения.

#### 2.9. Статистика и отслеживание прогресса

Для анализа продуктивности пользователя необходимо реализовать отдельный раздел статистики.

Раздел должен отображать:
- общее количество созданных задач;
- количество выполненных задач;
- количество активных задач;
- количество просроченных задач;
- процент выполнения задач;
- статистику выполнения за определённый период;
- распределение задач по категориям;
- соотношение выполненных и невыполненных задач.

Для наглядного представления информации рекомендуется использовать круговые и столбчатые диаграммы.

Процент выполнения задач должен рассчитываться на основе соотношения количества выполненных задач к общему количеству задач, учитываемых в статистике.

#### 2.10. Настройки приложения

В приложении должен присутствовать отдельный раздел настроек.

Необходимо предусмотреть:
- изменение имени пользователя;
- настройку внешнего вида приложения;
- выбор светлой или тёмной темы (дополнительная возможность);
- настройку стандартного времени напоминаний;
- настройку формата отображения даты и времени;
- управление категориями.

Настройки должны сохраняться между запусками приложения.

### 3. Требования к пользовательскому интерфейсу

Интерфейс приложения должен быть современным, минималистичным и интуитивно понятным.

При разработке интерфейса необходимо ориентироваться на визуальные решения Google Calendar, Todoist и аналогичных приложений для управления временем.

**Основные элементы интерфейса:**
- главное окно приложения;
- боковая панель навигации;
- рабочая область выбранного раздела;
- формы создания и редактирования задач;
- календарная сетка;
- списки задач и событий;
- панели фильтрации и поиска;
- информационные карточки;
- элементы отображения статистики.

**Дополнительные требования:**
- единый стиль оформления всех разделов;
- удобная навигация;
- визуальное выделение важных и просроченных задач;
- цветовое обозначение категорий;
- возможность изменения размеров главного окна;
- использование всплывающих окон для создания и редактирования элементов;
- корректное отображение информации при изменении размеров окна.

### 5. Архитектура приложения

Разрабатываемое приложение должно быть построено с использованием архитектурного шаблона MVVM (Model-View-ViewModel).

Данный подход обеспечивает разделение графического интерфейса, данных и логики приложения.

**Model**

Отвечает за описание объектов предметной области и структуру данных.

Основные модели:
- Task;
- Event;
- Category;
- Reminder;
- Notification;
- AppSettings.

**View**

Отвечает за отображение графического интерфейса приложения.

Представляет собой XAML-файлы, содержащие разметку окон, страниц, кнопок, таблиц и других элементов управления.

**ViewModel**

Обеспечивает взаимодействие между интерфейсом и моделями данных.

Отвечает за:
- обработку действий пользователя;
- выполнение команд;
- передачу данных в интерфейс;
- обновление отображаемой информации;
- вызов методов сервисов.

**Services**

Содержит классы, реализующие основную бизнес-логику приложения.

Предполагаемые сервисы:
- TaskService — управление задачами;
- CalendarService — получение и обработка календарных данных;
- EventService — управление событиями;
- ReminderService — обработка напоминаний;
- StatisticsService — формирование статистики.

**Data**

Содержит контекст базы данных и настройки взаимодействия с SQLite.

### 6. Требования к базе данных

Для хранения информации необходимо использовать SQLite.

В системе должны быть предусмотрены следующие основные сущности.

**6.1. Task (Задача)**

- Id — идентификатор;
- Title — название;
- Description — описание;
- CreatedAt — дата создания;
- DueDate — срок выполнения;
- StartDate — дата начала (необязательно);
- Priority — приоритет;
- Status — статус;
- CategoryId — идентификатор категории;
- ReminderId — идентификатор напоминания (при необходимости).

**6.2. Event (Событие)**

- Id — идентификатор;
- Title — название;
- Description — описание;
- StartDateTime — дата и время начала;
- EndDateTime — дата и время окончания;
- Location — место проведения;
- CategoryId — идентификатор категории.

**6.3. Category (Категория)**

- Id — идентификатор;
- Name — название;
- Color — цветовое обозначение.

**6.4. Reminder (Напоминание)**

- Id — идентификатор;
- ReminderDateTime — дата и время напоминания;
- IsSent — признак отправленного уведомления;
- TaskId — идентификатор задачи (необязательно);
- EventId — идентификатор события (необязательно).

**6.5. Notification (Уведомление)**

- Id — идентификатор;
- Title — заголовок;
- Message — текст уведомления;
- CreatedAt — дата создания;
- IsRead — признак прочитанного уведомления.

**6.6. AppSettings (Настройки приложения)**

- Id — идентификатор;
- UserName — имя пользователя;
- Theme — выбранная тема;
- DateFormat — формат даты;
- DefaultReminderTime — стандартное время напоминания.

Между сущностями должны быть установлены необходимые связи.

Одна категория может содержать несколько задач и событий. Каждая задача или событие может относиться к одной категории.

Напоминание должно быть связано с соответствующей задачей или событием.

### 7. Нефункциональные требования

Разрабатываемое приложение должно соответствовать следующим требованиям:

- корректная обработка пользовательского ввода;
- проверка обязательных полей;
- предотвращение сохранения некорректных данных;
- обработка ошибок при взаимодействии с базой данных;
- проверка корректности временных интервалов;
- сохранение данных между запусками приложения;
- удобная навигация между разделами;
- отсутствие необходимости постоянного подключения к интернету;
- корректная работа с локальной базой данных;
- понятные сообщения об ошибках;
- поддержка операционной системы Windows.

### 8. Дополнительные возможности

При наличии времени допускается расширение функциональности приложения.

Возможные дополнительные модули:

1. **Повторяющиеся задачи и события.** Возможность настроить ежедневное, еженедельное или ежемесячное повторение.
2. **Drag & Drop.** Перемещение задач и событий непосредственно в календаре с помощью перетаскивания.
3. **Pomodoro Timer.** Таймер для организации рабочего времени и перерывов.
4. **Прикрепление файлов.** Возможность добавлять документы к задачам.
5. **Экспорт календаря.** Выгрузка событий в формате iCalendar (.ics).
6. **Импорт событий.** Загрузка календарных событий из файла.
7. **Горячие клавиши.** Быстрое создание задач и переключение между разделами.
8. **Системные уведомления Windows.** Отображение напоминаний даже при свёрнутом окне приложения.
9. **Планирование повторяющихся задач.** Автоматическое создание задач по установленному расписанию.

### 9. Ожидаемый результат

Результатом выполнения курсового проекта должно стать полноценное настольное приложение TaskFlow, предоставляющее пользователю единое пространство для управления повседневными задачами и календарного планирования.

Разработанная программа должна обеспечивать возможность создавать, редактировать и удалять задачи и события, распределять их по категориям, назначать сроки выполнения и напоминания, просматривать расписание в календаре и анализировать прогресс выполнения задач.

Приложение должно обладать современным графическим интерфейсом, удобной навигацией, локальной базой данных и возможностью дальнейшего расширения функциональности.
